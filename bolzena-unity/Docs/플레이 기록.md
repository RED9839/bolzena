# 플레이 기록

볼제나 웹판(bolzena.pages.dev)은 판이 끝날 때 그 판의 **익명 기록 한 장**을 보낸다. 봇 시뮬(`bz sim`)으로는 안 보이는 것 —
사람이 어떤 사도를 고르고, 어떤 카드 · 신탁 · 진급 보상을 집고, 어디서 무너지는지 — 를 보고 밸런스를 다듬으려는 것이다.

- 기록을 짓는 곳: `bolzena-core` `Runtime/Run/RunRecord.cs`(`RunRecord.Of` — 순수 함수, 봇 판에도 그대로) · 턴 녹화 `Runtime/Combat/BattleTape.cs` · 선택 적기 `RecState.Picks`(Run 이 고를 때마다)
- 보내는 곳: `bolzena-runui` `Runtime/Kit/PlayRecord.cs`
- 받는 곳: `bolzena-unity/Web/functions/api/record.js`(Cloudflare Pages Functions) → KV `bolzena-records`
- 모으는 곳: `bz records pull` · `bz records`(`bolzena-core/Tools~/Dev/Records.cs`)

## 개인 정보 — 담지 않는다

| 넣는 것 | 넣지 않는 것 |
|---|---|
| 기기 무작위 익명 id(처음 실행 때 만든 32자 — `PlayerPrefs bz.rec.anon`) | 이름 · 이메일 · 계정 · 진행 코드 · 세이브 내용 |
| 게임 버전 · 빌드 시각 | IP · User-Agent · 화면 해상도 · 언어 · 시간대 |
| 플랫폼 갈래(web · pc) · 폰인가 · 저사양 모드인가 | 기기 모델 · 브라우저 |
| 판 내용(편성 · 카드 · 전투 · 선택) · 시작/끝 시각(**분까지**, UTC) | 초 단위 시각 · 입력 기록 |

- 익명 id 는 진행 코드(교주 보드 · 프리셋)와 무관하다 — 진행 코드에 안 들어가고, 진행 코드를 다른 기기에 옮겨도 id 는 따라가지 않는다.
- 받는 쪽은 IP 를 KV 에 쓰지 않는다(분당 횟수 막기에 그 서버 조각 메모리에서만 잠깐 쓴다). 읽는 공개 주소는 없다 — wrangler 로그인한 사람만 읽는다.
- 180일 뒤 저절로 지워진다.

## 언제 보내나

| 때 | result | 부르는 곳 |
|---|---|---|
| 2층 보스를 이김 | `win` | `Flow.End("clear")` |
| 파티가 쓰러짐 | `lose` | `Flow.End("lose")` |
| 로비 「새 모험 → 버리고 출발」 | `abandon` | `Flow.Lobby` (저장된 판을 읽어 `RunPort.SavedRun`) |
| 설정 「로비로(모험은 저장)」 · 전투 일시정지 「메인 화면으로」 | `quit` | `Flow.Panels` · `BattleBridge.LeaveToLobby` |

- `quit` 은 판이 아직 이어질 수 있는 중간 기록이다. 나중에 같은 판이 끝나면 또 한 장 — 모을 때 (익명 id, 씨앗)마다 **끝난 쪽**(없으면 늦은 쪽) 하나만 센다.
- 브라우저 탭을 그냥 닫은 판은 안 간다(이어하기로 돌아와 끝내면 그때 간다).
- **보내는 것은 웹 배포판뿐** — `PlayRecord.Allowed`: WebGL 플레이어 · 주소가 http(s) · 호스트가 localhost · 127.0.0.1 · `.local` 이 아님 · 시험 실행 아님.
  - 에디터 · PC 빌드 · 데모(`Demo.Active`) · 시험 인자(`TestMute` 의 `-demo` `-battle` … · `-norec` · `-recdir`)는 **보내지 않고 파일로 남긴다** — `-recdir 폴더`(없으면 `persistentDataPath/play-records`, 최근 20장), 이름 `볼제나-기록-<UTC>-<씨앗>-<결과>.json`.
- 설정 「플레이 기록 보내기(익명)」(화면 탭 맨 아래, 기본 켬 · `bz.rec.send`)를 끄면 보내지 않는다.
- 처음 실행 때 로비에서 한 번 알림: 「밸런스를 다듬으려고 판 기록을 익명으로 보냅니다. 개인 정보는 없고, 설정에서 끌 수 있습니다.」(`bz.rec.noticed`)
- 실패하면(네트워크 · 429 · 5xx) `persistentDataPath/rec-queue/` 에 **5장까지** 두었다가 다음 실행 8초 뒤 다시 보낸다. 400 · 403 · 410 · 413 은 버린다. 판 세이브(`bolzena-run.json`) · 진행 코드와 파일이 섞이지 않는다.
- 보내기 전에 `RunRecord.Check`(받는 쪽과 같은 검사)를 지나야 한다.

점검:
- `-demo -demo-rec [-recdir 폴더] -mute -save 다른이름.json` — 안내 한 줄 · 설정 스위치를 찍고(`rec_notice` · `rec_settings`), 짧은 판을 져서 끝 기록이 파일로 남는지 · 검사를 지나는지 단언한다(runui `Demo.Record.cs`). 웹 빌드는 헤드리스 크롬 하네스(`BZ_ARGS='["-demo","-demo-rec","-mute"]'`)로.
- 에디터 배치: `Unity.exe -batchmode -quit -projectPath C:/projects/bolzena-unity -executeMethod Bolzena.RunUI.EditorTools.PlayRecordCheck.Run -recdir 폴더` — 봇 판 몇 개를 끝까지 하고 남은 파일을 검사한다.
- 엔진: `bolzena-core` `Tests/Editor/PlayRecordTests.cs`.

## 형식 v2

`kind: "bolzena-record"` · `v: 2` · `app: "unity"`. JSON 은 camelCase, **0 · 빈 값 · false 는 빠진다**(없으면 0).

| 키 | 뜻 |
|---|---|
| `anon` · `ver` · `build` | 익명 id · `Application.version` · 빌드 시각(`Assets/Resources/RunUI/build_stamp.txt` — runui `Editor/BuildStamp.cs` 가 빌드 때 적는다) |
| `os` · `phone` · `low` | web · pc · editor(봇은 bot) · 폰 · 저사양 모드 |
| `seed` · `village` · `nature` | 판 씨앗 · 마을 · 판의 적 속성 |
| `began` · `ended` · `min` | 시작 · 끝(UTC 분) · 걸린 분 |
| `result` | win · lose · abandon · quit |
| `party` | `[{id, slot}]` — slot 1 = 맨 앞 |
| `floor` · `node` · `step` · `at` | 도달 층(1 · 2) · 싸움 세기(0..2, 3 보스) · 걸음 · 마지막 칸 종류 |
| `grade` · `credits` · `board` | 학년 · 학점 · 교주 보드에 칠한 단계 수 |
| `fast` | 전투 시간 가운데 2배속이던 몫(0~1) |
| `gold` · `hp` · `maxHp` · `removals` | 끝날 때 골드 · 파티 HP · 상점 빼기 횟수 |
| `fights[]` | 싸움마다 `floor · node · kind(fight · elite · boss · event) · foes(적 id) · result · turns · hpBefore · hpAfter · hpMax · plays(낸 카드) · ults(고학년) · deck(그때 덱의 카드 종류) · log(턴별)` |
| `fights[].log[]` | 턴마다 `t` 턴 · `c` 낸 카드(차례대로 — `/o3` 신탁 3, 앞의 `+` 는 그 싸움 중 생긴 카드) · `d` 받은 피해(HP) · `b` 막은 양 · `hp` 턴 끝 파티 HP · `u` 고학년 수 · `f` 적의 수 `[{e 적 id, a 수 갈래, d 그 수로 받은 피해(막은 몫 포함)}]` |
| `picks[]` | 선택 `{k, f 층, s 걸음, card 대상, at, offer 제시된 것, pick 고른 것(없으면 넘김)}` — 아래 |
| `deck` · `arts` | 끝날 때 덱 `[{id, n, o 신탁, b 축복}]` · 사도 → 칸 → 아티팩트 id |
| `death` | 쓰러진 곳 `{f, n, k, turn, foes(그때 적), hp(그 싸움 시작 파티 HP), maxHp}` |
| `trim` | 크기 상한으로 줄인 단계(아래) |

`picks[].k` — `grace`(은총: offer · pick 은 고유 카드 id, `card` 는 빛난 카드) · `oracle`(신탁: 번호, `at: "fight"` 면 전투 중 낼 때 고름, 없으면 끝난 뒤 보상 · 진급 신탁) · `equip`(전리품 아티팩트) · `grade`(진급 보상 종류, `card` 받은 것) · `shop`(진열 — offer 만) · `buy` · `remove`(상점 빼기) · `gradeRemove` · `train`(휴식 수련 = 강화: 신탁 번호) · `rest` · `copy`(보스 복제) · `event`(offer 이벤트 id, pick 선택지 차례) · `ev.card` · `ev.flash` · `ev.remove` · `ev.grace` · `ev.dupe` · `ev.shinPick` · `ev.gambleChoice`.

**크기** — 한 판 보통 10~25KB(봇 40판: 가운데 11KB · 가장 큰 것 21KB). 상한 **64KB** 를 넘으면 차례로 줄인다(`RunRecord.Shrink`):
① 이긴 일반 · 이벤트 싸움의 `log` · `deck`(앞 싸움부터) → ② 상점 진열 → ③ 모든 `offer` → ④ `picks` 통째 → ⑤ 남은 `log`(엘리트 · 보스 · 진 싸움) → ⑥ 끝 덱. 줄인 단계는 `trim`.

## 받는 쪽 — `/api/record`

`bolzena-unity/Web/functions/api/record.js`(POST 만, 그 밖은 405).

- 검사: `kind` · `v: 2` · `app: "unity"` · 위쪽 키 **허용 목록**(모르는 키가 있으면 400 — 다른 것을 끼워 넣지 못하게) · `anon` 16진 16~64자 · `seed` 정수 · `result` 넷 가운데 · `party` 1~4 · `fights` ≤ 80(턴 ≤ 60) · `picks` ≤ 1500 · 시각 꼴 · 크기 **64KB**(413).
- 옛 v1(웹판 「2층 보스 전 · 뒤」 기록)은 **받지 않는다**(410) — 웹(JS)판이 2026-10-05 에 내려가 보내는 곳이 없다. 예전 `rec/…` 키(90일)는 KV 에 남아 있다가 저절로 지워진다.
- 키: `v2/<yyyymmdd — 받은 날 UTC>/<익명 id>/<씨앗>/<결과>` · TTL **180일**. 같은 날 같은 판 · 같은 결과는 덮어쓴다.
- 남용 막기: 다른 사이트 Origin 이면 403 · 같은 IP 분당 6번(그 서버 조각 메모리 — 느슨함, KV 에 IP 를 안 쓴다) 429 · KV 쓰기 실패(무료 하루 1000번 따위)는 503 — 게임이 다음 실행 때 다시 보낸다.
  - 판 하나가 많아야 2~3장(quit 몇 번 + 끝)이라 하루 300판쯤까지는 무료 한도 안이다. 넘칠 만큼 모이면 Workers 유료(쓰기 100만/월)로 올리거나 quit 을 빼면 된다.
- 응답: 204(받음).

로컬 시험(운영 KV 에 안 쓴다 — 로컬 KV 파일):

```sh
cd C:/projects/bolzena-unity/Web
npx wrangler pages dev --port 8799 --ip 127.0.0.1 --persist-to <시험 폴더>
curl -X POST --data-binary @기록.json http://127.0.0.1:8799/api/record     # 204
bz records pull --local <시험 폴더> --out <받을 폴더>                       # 로컬 KV 에서 받아 보기
```

## 배포 — 바뀐 점

예전에는 `C:\Users\User` 에서 `npx wrangler pages deploy C:/projects/bolzena-unity/WebBuild …` 로 올려 **`functions/` 가 빠졌다**(2026-10-09 확인: `GET /api/record` 가 index.html 200 — 함수 없음). KV 바인딩 `RECORDS` 는 Pages 프로젝트(production)에 남아 있다(`wrangler pages download config bolzena`).

이제는 **`bolzena-unity/Web` 폴더에서** 올린다 — wrangler 는 돌린 폴더의 `functions/` 를 함께 올리고, `wrangler.toml` 의 `pages_build_output_dir = "../WebBuild"` 를 정적 파일로 쓴다(KV 바인딩도 이 파일이 정한다):

```sh
# 1) 빌드(바뀐 것 없음)
cd C:/projects/bolzena-unity && ./Tools/build_web.sh
# 2) 배포 — Web 폴더에서(디렉터리 인자 없이)
cd C:/projects/bolzena-unity/Web && npx wrangler pages deploy --project-name bolzena --branch main --commit-dirty=true
# 3) 확인 — 함수가 붙었나(POST 하지 않는다)
curl -s -o /dev/null -w "%{http_code}\n" https://bolzena.pages.dev/api/record     # 405 면 붙음(200 이면 함수가 빠졌다)
```

- 배포 출력에 `✨ Compiled Worker successfully` · `Uploading Functions bundle` 가 보여야 한다.
- 처음 몇 판 뒤 `bz records pull` 로 기록이 들어오는지 본다.

## 모으기

```sh
# KV → C:\projects\bolzena-records\ (저장소 밖 · 이미 받은 키는 건너뜀 · wrangler 로그인 필요 · 읽기만)
bz records pull [--out 폴더]
# 모아 보기 + 같은 편성으로 돌린 봇 판과 나란히(데이터는 --data 없으면 bolzena-content-v2)
bz records [폴더] [--sim 200] [--bot skilled|basic] [--seed 0] [--out 보고.md] [--dump 봇기록폴더]
```

(`bz` = `bolzena-core/Tools~/Dev/bz.cmd` — 엔진을 고친 뒤 `build.cmd` 로 다시 빌드.)

보고 표(사람 | 봇):
- 판 수 · **완주율**(승리 / 승리+패배+포기 — quit 만 남은 판은 뺀다) · 결과 분포 · 평균 판 시간(중앙값)
- 싸움 종류마다 횟수 · 평균 턴 · 잃은 HP(최대의 %)
- **층별 쓰러짐**(n층 일반 · 엘리트 · 보스) · **파티를 쓰러뜨린 적**
- **무너지는 턴** — 받은 피해가 그 싸움 최대 HP 의 25% 넘은 턴의 적 수(적 · 수 갈래마다 횟수 · 평균 피해)
- **사도별** 편성률 · 완주율
- **선택률** — 진급 보상 · 신탁(번호) · 은총 · 이벤트 카드 · 전리품 아티팩트 · 상점 구매 · 빼기 · 보스 복제(제시된 수 · 고른 비율, 「(넘김)」 줄)
- **카드 실제 사용률** — 낸 수 / 그 카드가 덱에 있던 싸움 수(싸움당)

봇 쪽은 사람 기록의 편성 · 마을을 돌려 써서(없으면 무작위) 같은 `RunRecord.Of` 로 기록을 짓는다 — 같은 지표를 같은 코드로 센다.
